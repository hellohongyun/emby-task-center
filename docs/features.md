# 功能与使用边界

Emby 网页地址和 PanSou 上游没有预设的个人服务地址，需在系统设置中填写自己的配置；PanSou 未配置时不会发送搜索请求。

## 虚拟媒体库

管理后台「虚拟媒体库」可以创建额外的媒体库，搜索并映射 Emby 已有电影和整部剧，不单独选入季、分集或其他类型。电影库只允许电影，剧集库只允许整部剧，混合库允许两者；前后端校验新增映射和库类型变更，历史关联保留，类型不匹配时提示。客户端连接本服务的独立反代入口后，同时看到原有库与虚拟库；影片 ID 和资料沿用上游，剧集的季与分集浏览仍保留，其他请求继续转发给 TgtoDrive，不添加额外会员、并发或原有操作限制。后台移除只解除关联，客户端原有真实删片仍由上游处理。配置、Docker 端口及实际客户端验证范围见 [虚拟媒体库](virtual-libraries.md)。

映射记录可用的 TMDB 身份，原 Emby ID 重建后仅按同类型、同 TMDB 的唯一候选重新关联；缺少身份、多候选或上游失败时保留关联并在后台提示。自动检查仅作用于虚拟库，客户端仍使用自身凭据，普通请求与播放链接不变。

每个虚拟库可上传独立的媒体库入口海报，支持预览、替换和移除；海报随 SQLite 数据持久化，不覆盖原影片／剧集海报。

名单逐项选片允许粘贴每行一个片名，依次填入现有搜索框；用户确认版本并加入成功后才搜索下一项，也可跳过。名单仅在当前页面暂存，切换虚拟库或离开页面后结束，不自动匹配、选片或改变原有加入规则。

## 媒体库作品浏览

管理端媒体库按电影和整部剧展示作品卡片。同一库内优先以媒体类型与有效 TMDB ID 识别作品，别名或年份差异不会拆开同一 TMDB 作品；缺少 TMDB ID 时按片名、年份与类型归组，不与已识别作品强行合并。类型优先采用已关联作品的电影或剧集类型，缺少关联类型时再根据分集编号判断，避免无分集记录的已识别剧集被标为电影。搜索覆盖同组内所有来源片名。各媒体库独立展示，点击剧集仍读取完整分集详情。此处只调整库存的读取与归组，不改变扫描、缺集统计或 Emby 原始条目；虚拟库仍使用原 Emby ID 映射。

手机端使用双列海报和紧凑统计，搜索始终可用，其他筛选通过「展开筛选」显示；收起筛选不清除已选条件。媒体详情弹窗适应手机高度，内容可独立滚动，底部导航预留安全区域。

## 同步与检测

Emby 提供媒体库与已存分集，TMDB 提供已播元数据。系统设置分别控制库存扫描、已播进度刷新和全库缺集检测，配置以数据库为准。

默认自适应库存扫描：发现新缺集可触发扫描，仍缺集时按 30 分钟周期检查，全部同步时按 60 分钟兜底；固定模式按配置周期扫描。已播进度默认每 10 分钟刷新，全库缺集检测默认每小时执行，周期可在系统设置调整或关闭。扫描合并、失败退避与缓存边界见 [性能说明](performance.md)。应用不发出 AI 唤醒，也没有 worker 认领片源入库的执行链路。

## 任务看板（任务中心）

任务中心展示已登记作品的已播、已存、缺集与媒体库归属，支持排序、筛选、分季查看和改绑 TMDB。管理员可通过「新建任务」搜索 TMDB 并登记作品，重复添加由服务端幂等处理；该入口登记任务与作品元数据，片源入库仍由外部流程完成。

- 行上显示：剧名 · TMDB 已播 · 库内已存 · **媒体库** · 缺几集 · 最后检查 · 状态胶囊；点行内箭头（手机端点卡片）展开，每季一行的季号 · 已播 · 已存 · **媒体库** · **缺哪几集**（如 E18、E210）。
- **媒体库**列说明"已存的这些集到底在哪个库"：每行是「Emby 库名 + 该库里去重后的集数」（例如「剧集 208 集」「动漫 206 集」），下面一行给出库内作品目录（如 `斗破苍穹 年番`），鼠标悬停可看完整目录；电影没有逐集明细，显示「已入库」。一集都没入库显示「未入库」，季行上则显示该季落在哪个库、库内哪个目录（如 `斗破苍穹 年番/Season 05`）。
- 同一部作品可能同时存在于多个库（例如「剧集」和「动漫」各有一份）：各库分别统计，行上的"已存"取**各库并集去重**后的集数，同一集在两库各存一份不会算成两集。
- 桌面端表头可点击排序（剧名 / 已播 / 已存 / 缺集 / 最后检查），筛选条为 全部 / 缺集中 / **今日更新** / 已齐 + **不限媒体库 / 各库名**（按"这条任务的已存出现在这个库里"过滤）；手机端是卡片 + 手风琴。
- **改绑 TMDB**：行内「改绑」（手机：卡片手风琴内）→ 二次搜 TMDB 选中正确条目，或直接**手填 TMDB ID**（搜不到时还能填标题兜底）→ 确认。改绑后按新条目重建分季与已播/今日更新进度、重算缺集；目标条目已在用时会**合并**到同一条（任务、库内片源关联、别名、提供方索引一起迁移，不产生重复条目），操作写入审计日志（`task.tmdb_rebound`）。库内片源在下一轮媒体库扫描时按 Emby 登记的标识重新对齐。

> 追更（follow）已整体下线（2026-09）：不再有持续追更/已完结标记、会员端追更页与订阅、新集自动检查、追更指标与审计分类、追更绑定 TMDB；数据库里的三张追更表（`follow_progress_logs` / `public_follow_requests` / `task_subscriptions`）、`media_tasks.track_mode` 列、`metric_daily` 表与历史追更任务行会在服务启动跑迁移+对账时自动清理（幂等，见 `packages/database/src/reconcile.ts`）。

### 已播与已存怎么算

- **已播**：TMDB 上该剧/该季已播出的集数，服务器定时刷新。
- **已存**：Emby 媒体库里已入库的集数，按"第几季第几集"逐集比对；同一集存在多个库时按并集只算一集，归属到哪个库由「媒体库」列给出。
- **缺哪几集**：已播集号减去库里实际存在的集号（逐集求差），所以能给出 `E18、E210` 这样的具体集号，而不是"已播减已存"的估算。
- **今日更新（入库宽限期）**：TMDB 的 `air_date` 只有日期没有时刻，"今天 18 点更新"从当天 00:00 起就算已播，而片源要到晚上才入库——按老口径早上 8 点就会看到一集假的"缺集"。现在某集在播出日当天 00:00 + 宽限期内**不计缺集**，页面单独标「今日更新 N 集」（状态胶囊也是中性蓝的「今日更新」，不是"缺集中"）；过了宽限期仍未入库就照常落进缺集，所以不会漏报。宽限期 = 系统设置 → 媒体库的 `library.missingGraceHours`（`MISSING_GRACE_HOURS`），默认 24 小时即次日 0 点起算，可调到 0–72；设 0 恢复旧口径（当天即算缺集）。已播数字本身不变（仍是 TMDB 的真实已播，含当天那一集）。

### 季号对不上时（TMDB 与 Emby 的季划分不一致）

典型例子《斗破苍穹》：TMDB 拆成 S1–S4 + S5 年番（已播 12+12+12+24+210 = 270），而 Emby 里只有一个 S5 装着年番的 208 集。逐季相减会把 S1–S4 的 60 集全算成"缺"。

现在的规则是**不臆造、也不静默丢弃**：

- 媒体库里**一集都没有**这个条目 → 整剧未入库，每季按"已播即缺"算；
- 有逐集明细、但**某一季没有记录** → 判定为季号对不上：该季标为"库内无此季号（未比对）"，从合计中排除，并在行上提示「S01、S02… 库内无对应季号（共 60 集），未计入」。

于是斗破显示的是 **已播 210 / 已存 208 / 缺 2（E18、E210）**，外加一条 4 季未纳入的提示。

> 表结构说明：`media_tasks` 等表里仍保留 `task_type='ingest'`、`last_played_at`、`recycled_at` 等列（不重建库），但已无写入方。

### 缺集总览（全库自动检测）

后台每小时刷新一轮作品的 TMDB 季集缓存（间隔可在系统设置 → 媒体库调整，0 关闭；启动后先跑一次）。缺集页面按**当前选中的启用媒体库**独立比对库存，其他库副本不补齐当前库，停用库不参与页面统计。历史库存和快照保留；**不依赖任务中心里有没有建过任务**。

- 按剧分组逐集列出 `S05E18 · 三年之约`（集名取自 TMDB zh-CN），并给出当前库的「已播 / 已存 / 缺几集」。默认第一个启用剧集/混合库，没有缺集的启用库仍可切换。搜索只作用于当前库，支持按缺集数/剧名排序，每 60 秒自动刷新；后台刷新时加快进度轮询，切库清除旧结果和勾选，离页取消请求与轮询。
- Emby 一个文件包含多集时，按 `IndexNumber` 至 `IndexNumberEnd` 的闭区间保存所有集号，一个真实 Emby 文件仍只保留一份库存。明确属于 S00 且起止集号均未提供的特别篇保留真实库存 ID、记录未编号提示，不生成虚假集号、不阻断正片同步；不同特别篇不因都没有编号而合并。正片缺号、非法范围或同 ID 身份冲突使扫描失败并保留旧库存；旧起始集库存通过成功的重扫补齐范围。
- **今日更新**：宽限期内（默认当天播出、次日 0 点前）还没入库的集单独标出、**不计缺集**，页头合计另给一句"另有 N 集今日更新待入库"；口径与任务看板完全一致（见上文「今日更新（入库宽限期）」）。**只差今日更新、没有其它缺集的剧也会列进清单**（标「仅今日更新待入库」、显示"无缺集"、排在有缺集的剧之后），但**不给勾选框、不进"全选当前"**，因此不会被批量删除——删除的对象始终是"缺集"。
- 编号口径按现实分五类处理（2026-09-19 用真实库全量对账后确定）：常规逐季编号直接逐集比对；Emby/TVDB 全剧连续绝对编号（如进击的巨人 S2 是 26–37）按 TMDB 全剧绝对位置比对；TMDB 全剧连续编号（如侠岚 S2 是 27–52、S3 是 53–78）换算成每季相对集号再比对（显示也用相对集号）；TVDB 半集合并 vs TMDB 分段（如海绵宝宝）列为「编号体系疑似不一致」只提示、不报缺集；库内没有对应季号的季列「未计入」。
- 删除前的集名兜底：重新读取当前库的 Emby 分集名称；若报缺的真实集名已存在于其他编号，整季降级为「疑似编号不一致」，不凭该季授权删除。"第 N 集"这类占位名不参与匹配。页面的本地库存未保存分集名称，因此页面不复用全库快照的集名判断；电影没有逐集概念，不在此页。
- 仅有编号疑似、未匹配季或元数据未完整检测的作品也会列出提示，不冒充「仅今日更新」或「已齐」，也不因此获得删除资格。缺少完整的 TMDB 季集缓存时不判定缺集。原全库快照的身份校验和父级条目 ID 不作为当前库专属事实使用。
- 当前库库存扫描失败或尚未完成时，页面提示库存同步不完整；即使结果为零也不显示「未发现缺集」。需先在媒体库页面完成库存扫描，「立即检测」仅刷新 TMDB 元数据。
- TMDB 季/集列表在服务端缓存 12 小时：缓存期内的小时级重算只用本地扫描数据，跨重启复用；TMDB 暂时不可用时用旧缓存重算并在行上标注。
- 页面可「立即检测」手动触发一轮并显示进度，检测期间仍展示上一轮结果。
- 点击「在 Emby 查看 ↗」时，应用按当前库解析真实剧集与季 ID，再跳到配置的 Emby 网页；没有季 ID 时回到当前库的剧集页，不复用其他库的旧链接。跳转使用管理端会话鉴权，不在 URL 携带 API Key。
- 勾选一部或多部剧可以批量删除，**仅限当前选中的媒体库**：调 Emby 官方的 `DELETE /Items/{Id}`（Emby 会按其策略联动片源清理，**不可恢复**），确认弹层列出库名与待删剧名。查询和删除统一使用上游媒体库 ID，不能回退解释为本地数据库行号。删除前完整读取所选库的真实条目与分集，展开合并集并复核缺集和集名保护；元数据不完整、读取失败、无实际缺集、归属或连接变化时不删。其他库副本与库存保留。操作写入审计日志，成功后清理当前库库存并使汇总缓存失效；其他库仍有副本时保留共享快照，最后一份库存删除后才清除共享快照。
- 说明：Emby 本身没有可用的「遗漏集」接口（实测 4.10 的 `Filters=IsMissing` 被忽略、也不生成虚拟缺失集），缺集只能由 TMDB 这类外部元数据来判定。

## 公开门户与会员

管理端卡密页面为 `/login/cardKeys`，桌面从侧栏「卡密」进入，手机从底部「更多 → 卡密」进入。

卡密页按创建表单、可选祝福文案和卡密列表分区。手机端表单与操作适应窄屏，列表按卡片展示名称、类型、到期、状态和使用信息，保留复制及行内编辑；桌面端保留表格。布局调整不改变卡密生成、兑换、到期或删除规则。

**管理后台在 `/login`**（管理员账号登录），**会员门户在 `/`**（无需管理端登录）。门户提供影视内容浏览、会员资料、账号管理与续费，没有投稿入口。

- **会员识别**：`submission_users` 表记录会员邮箱（`enabled` + `subscription_expires_at` + 可选 `emby_username` 映射 + 并发上限 + 备注 + 历史遗留的额度字段）。会员用**邮箱 + 验证码**登录，会话独立于管理端。
- **门户三个页面**：首页（热榜：豆瓣 / TMDB / IMDB / 奈飞，标注"可看"的已在库）、影视库（启用媒体库检索 + 详情弹层判断"可看 / 本库暂无"）、我的（会员状态与到期、Emby 账号与改密、卡密兑换续费、邮件偏好、平台须知）。停用库退出当前库存统计、门户影视库和“可看”判断；库存记录与扫描历史保留，重新启用后恢复展示。
- **会员生命周期**：到期前 3 天发"即将到期"邮件并在管理端标黄；到期发"已过期"邮件、管理端标红，配置了 Emby 集成时定时停用对应 Emby 用户（每 6 小时检查，单用户失败不阻断）。过期会员只可进入“我的”查看资料和续费；管理员停用阻止登录及已有会话。续费仅在会员启用、有效且未冻结时恢复 Emby，不能绕过并发冻结；管理员手工改到期时间不会自动恢复。提醒投递成功后才记录状态，失败下轮重试；SMTP 与写库之间退出仍可能重复提醒。完整规则见 [会员访问与账号恢复](member-access.md)。
- **在线会话详情**：管理端「会员与运营 → 会员」里的会话卡片对齐 Emby 客户端的播放状态——剧名 S4E4 · 集名、`4:39 / 21:07`、设备与客户端版本、来源 IP、直接播放 / 直接串流 / 转码、容器与码率（MKV 6 mbps）、视频（4K HEVC）、音轨（Chinese EAC3 stereo）、字幕；转码时一并给出原因（容器不支持 / 视频编码不支持…）。列表默认只铺**正在播放**的会话，挂着的会话折叠成一行；**总时长未知**时（`.strm` / 网盘直链片源 Emby 里没有 RunTimeTicks）只显示「已播 47:58 · 总时长未知」+ 不确定态进度条，不会画成 0% 的空条。
- **会员使用记录**：「会员与运营 → 使用记录」按小时回答**谁在什么时候登录、看了什么、一天里的哪些时段在用**（全站 24 格时段分布 + 每会员时段条 + 单会员事件时间线与日期×小时热力图）。数据由应用自己攒：每 30 秒采样一次 Emby 在线会话（区间制，见 [docs/member-usage-records.md](member-usage-records.md)），并回填 Emby 活动日志里的登录/播放历史；采样间隔与保留天数在「系统设置 → 会员使用记录」调整。
- **访问边界**：管理端 API 由管理员会话保护；会员登录、开户、续费、自助解冻、改密与邮件偏好有各自校验。会员会话与管理员会话的签名用途隔离，内容访问按会员当前状态检查；详见 [会员访问与账号恢复](member-access.md)。
