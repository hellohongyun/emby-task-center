# 虚拟媒体库市场与个人排序需求

状态：已纳入 1.5.6，实际播放器版本仍需部署联调验收。本文保留已确认的目标规则和验收清单，具体操作见[虚拟媒体库](virtual-libraries.md)。

本轮以 1.5.5 为基线开发，市场功能从 1.5.6 起交付。下文原先待决策项已按用户确认记录在第 10 节，不能沿用此前已被替换的审批、复制公共副本或全员强制排序方案。

## 1. 目标与核心决策

用户和管理员均可创建虚拟媒体库，将自己的库上架市场。其他用户按需启用，播放器展示各自选择的媒体库，并保存各自的排列顺序。

已确认的核心规则：

1. 上架前后始终是同一个虚拟库，不复制为独立公共版本。
2. 库名称、海报和影片关联由创建者维护，无需管理员审核；修改同步给所有启用者。
3. 启用者获得使用权，不获得编辑权。管理员维护自己创建的库，不接管其他作者的日常维护。
4. 作者下架后，所有其他用户立即失去对该虚拟库的订阅及播放器访问，作者自己的库保留；管理员后台只读查看按第 3.3 节执行。
5. 所有本项目通用虚拟库改为市场订阅制，包括管理员创建及升级前已有的通用虚拟库。
6. 管理员可以指定新注册用户默认启用的市场库；已有用户的自主选择不被默认设置覆盖。
7. 用户可以统一排列本人可见的实体库、自有虚拟库和订阅虚拟库。私人库默认置前，但不再强制固定在前面。
8. 管理员在后台可以只读查看每个用户创建的私人虚拟库及内容。

## 2. 媒体库分类与可见性

上架状态与订阅关系用于分享和展示，不把一份库拆成多份。下表是用户看到的三种来源：

| 类别 | 来源及归属 | 本人的展示条件 | 内容维护者 |
| --- | --- | --- | --- |
| Emby 实体媒体库 | 原 Emby 服务 | 沿用 Emby 原有授权和展示规则，不要求市场订阅 | 沿用 Emby 原规则 |
| 自有私人虚拟媒体库 | 本人创建，可未上架或已上架 | 创建者可见，按对应管理端或会员身份认证 | 创建者 |
| 订阅虚拟媒体库 | 其他用户或管理员创建并上架 | 库仍在架，且本人已启用 | 原创建者 |

管理员创建的虚拟库不再因为创建者是管理员而自动向所有人展示。用户自己的已上架库仍是自有库，不因额外启用而重复出现。

市场确认范围是本项目创建和维护的虚拟库。TgtoDrive 等上游动态注入库继续沿用上游可见性和排序兼容，不在本轮转换为市场库。

## 3. 所有权与权限

### 3.1 作者权限

- 创建、改名、修改类型、管理海报、搜索添加已有电影或整部剧、移除影片关联。
- 自主上架或下架自己的库，无需申请审核。
- 对自己已上架库的修改直接生效，所有启用者读取同一份最新数据。
- 沿用现有电影／剧集／混合类型约束；跨类型排序不取消单个库的内容类型校验。
- 会员作者选片沿用绑定 Emby 账号的可见范围；管理员作者沿用现有管理端选片范围，不新增必须绑定会员账号的要求。启用者始终按自身 Emby 权限读取影片，不借市场扩大权限。

### 3.2 订阅者权限

- 浏览市场中的已上架库，启用或关闭自己感兴趣的库。
- 查看、播放自己有 Emby 访问权限的影片，调整自己播放器中的库顺序。
- 不能修改他人库的名称、海报、影片关联、上架状态或其他用户的订阅与顺序。
- 关闭订阅只影响本人，不删除源库、作者数据或其他人的订阅。

### 3.3 管理员权限

- 作为作者维护自己创建的库，自主上架和下架。
- 在后台按用户查看私人库的名称、海报、内容及上架状态，此入口使用管理员认证。
- 查看他人的私人库不等于可以代编辑、代删除、代上架或代下架。
- 设置默认顺序模板和新用户默认启用库，不覆盖已有个人设置。
- 不新增对他人市场库名称、海报或内容的审核流程。

管理员只读查看是后台能力，不使该管理员关联的 Emby 播放器账号自动获得其他人的私人库，也不赋予额外的源影片播放权限。

## 4. 市场与订阅流程

### 4.1 上架与更新

作者在自己的虚拟库管理中选择上架，市场展示同一个库。其他用户启用后，其播放器中出现该库。

市场预览与播放器访问需要区分：未启用者仍可在市场看到在架库的名称、海报等介绍，才能决定是否启用；这不等于获得播放器库入口或库内容的访问权。市场预览接口须检查在架状态，下架后其他用户不能继续读取预览。未启用者不预览影片清单和作者的真实影片数量。

作者改名、换海报、增删影片时，库的稳定标识不变，订阅关系和个人排序继续指向同一个库。服务端后续请求返回更新内容；播放器界面的实际刷新受客户端缓存和刷新机制影响。

本需求没有独立发布副本、修改审批或每个订阅者复制内容的机制。

### 4.2 启用与关闭

- 启用保存当前用户与该库的关系，不为订阅者复制库或影片关联。
- 重复启用、重复关闭应具有幂等行为，不产生重复库入口。
- 用户关闭后，该库退出本人播放器的发现列表、库详情和库内容访问范围；在架时仍可在市场预览并重新启用。
- 关闭前已经获取的真实影片仍按上游权限处理，不通过关闭虚拟库修改实体媒体或原有播放权限。

### 4.3 下架与撤销访问

作者下架后：

1. 市场不再提供该库的新启用入口。
2. 所有其他用户的订阅及播放器访问立即撤销，即使此前已启用；管理员经后台认证的只读查看仍按第 3.3 节执行。
3. 发现列表、首页分区、详情、内容、海报和直接引用库 ID 的请求均遵循撤权结果。
4. 作者自己的库、影片关联和海报继续保留。
5. 客户端下次刷新后移除入口；旧缓存不能作为服务端继续授权的依据。

撤销的是虚拟库访问，不承诺收回客户端已经缓存的图片或资料，也不把下架实现为删除源影片、停用 Emby 账号或强制终止上游播放。

重新上架后原订阅不自动恢复，需要用户手动重新启用。

## 5. 新用户默认启用

管理员在「新用户默认设置」选择一个或多个已上架市场库，而不是让新用户自动订阅整个市场。

- 新用户注册完成时，按当时默认名单初始化启用关系。
- 仅对当时仍可启用的在架库生效；默认名单不能绕过下架限制。
- 用户此后可以自行关闭默认库，或启用其他市场库。
- 修改名单只影响以后新注册的用户，不给已有用户补开、重开或关闭任何库。
- 默认初始化应只执行一次；重复注册回调、登录或服务重启不能恢复用户已经关闭的默认库。
- 默认初始化仅用于门户首次注册；管理员创建、自动收编及导入不自动应用。

## 6. 每个用户的媒体库顺序

### 6.1 基本原则

使用「管理员默认模板＋个人顺序」。模板提供初始顺序和恢复默认的依据；用户一旦保存个人顺序，其个人选择优先。

所有排序都先计算用户当前可见的库，再排列该集合。排序记录中的库 ID 不能作为授权依据，不能让未启用、已下架或不属于本人的库重新出现。

用户通过「我的媒体库顺序」统一拖动三种来源的库，不强制按来源分组。媒体库依稳定标识排序，改名、修改海报和影片数量变化不改变位置。

### 6.2 已确认的排序规则

| 场景 | 目标行为 |
| --- | --- |
| 新用户或未保存个人顺序 | 自有库默认靠前；其余按管理员模板中当前可见的部分排列 |
| 用户保存个人顺序 | 只影响本人，允许实体库、自有库、订阅库混合排列 |
| 新建私人库 | 默认插到最前面，之后允许用户移动 |
| 新启用一个市场库 | 默认追加到末尾，不重排已有库 |
| 关闭订阅或作者下架 | 移除对应可见入口，其余库保持相对顺序 |
| 名称、海报或内容更新 | 保留该库的位置和身份，不生成新的排序项 |
| 管理员修改默认模板 | 不覆盖已经保存个人顺序的用户 |
| 用户选择恢复默认 | 对当前可见库重新应用管理员模板；模板外库保持相对顺序 |

恢复默认后的私人库默认置前，但用户仍可再次自由调整。个人排序必须持久化，刷新、重新登录和服务重启后保留。

同一用户的不同客户端通过本项目反代查询时，服务端应返回相同的可见集合和顺序。播放器自行按名称等条件重排时的界面行为需要实机验证，不能仅凭接口顺序宣布全部客户端一致。

## 7. 页面与操作调整

下列为目标页面职责，具体路由、接口和布局待实现时设计。

| 页面 | 目标职责 |
| --- | --- |
| 管理员「我的虚拟媒体库」 | 管理自己创建的库，展示上架状态，自主上下架 |
| 管理员「用户媒体库查看」 | 按用户只读查看其库、内容和分享状态 |
| 管理员「默认媒体库顺序」 | 配置实体库及市场库的默认模板，不再将模板强制覆盖所有用户 |
| 管理员「新用户默认设置」 | 选择新注册用户默认启用的已上架市场库 |
| 管理员播放器账号面板 | 独立显示绑定状态、选择对应 Emby 账号并保存；不与新用户默认名单混在一个表单 |
| 虚拟媒体库市场 | 浏览已上架库、查看库信息、启用或关闭；管理员也可使用市场能力 |
| 用户「我的虚拟媒体库」 | 继续管理自己的库，增加上下架操作；不用维护另一份市场副本 |
| 用户「我的媒体库顺序」 | 统一调整当前可见库顺序，支持保存和恢复默认 |

原管理端「同步到全部账号」不能原样保留为覆盖个人顺序的常规操作；需要根据新规则改造，并明确其与 Emby 原生 `OrderedViews`、反代默认模板的关系。

实体库是否可见仍由 Emby 决定，市场启停不是设置原生实体库访问权限的入口。

页面需分别呈现当前状态、操作和保存结果：市场卡片有独立的启用／自有状态，作者列表有上架状态；排序显示来源和序号，排序与默认设置标记未保存变更并允许撤销。请求失败保留原有启用状态和表单修改，切换标签不能静默丢弃未保存内容。管理员绑定和新用户默认名单各自使用部分更新，不能互相覆盖。

## 8. 数据及实现约束

以下描述实现需要表达的关系，不规定现有数据库已有对应字段或接口：

- 虚拟库：稳定 ID、明确创建者、原有名称／类型／海报／内容、上架状态。
- 用户订阅：用户与市场库的启用关系，同一用户同一库不能重复。
- 用户顺序：当前用户针对稳定库 ID 的排序及是否已有个人设置。
- 管理员默认设置：默认顺序模板、新注册用户默认启用库名单。

创建者身份必须覆盖管理员和普通会员，不能仅用旧数据「所属会员为空」推断新市场库可以由任意管理员编辑。新增的管理员只读查看能力需要与作者写权限分开。

播放器身份继续使用经过验证的客户端凭据；不能只凭请求中的 UserId、库 ID、DeviceId 或排序记录确定所属账号。会员有效期、停用、冻结与源影片权限沿用现有边界。

统一的可见性和排序结果需要覆盖 Views、根 Items、MediaFolders、首页分区及相关详情读取；先得到完整可见集合并排序，再正确分页，避免多私人库挤掉公共订阅库或产生重复、遗漏和错误总数。影片筛选请求仍保留原语义，不能全部误当作媒体库发现。

下架、关闭订阅及权限变化必须使相关授权判断和缓存及时失效，不能等待旧缓存自然过期后才撤权。源影片及播放透传仍使用原客户端权限，不借管理员 API Key 为订阅者扩大访问范围。

## 9. 已有数据与行为迁移

已确认要改变的行为：

| 当前行为（1.5.5） | 市场功能目标 |
| --- | --- |
| 管理员公共库默认全员可见 | 纳入市场，依订阅和在架状态决定他人可见性 |
| 私人库强制排在最前面 | 默认置前，但个人可自由移动 |
| 管理员排序优先覆盖发现列表 | 管理员提供默认模板，个人设置优先 |
| 管理接口不列出会员私人库 | 增加独立的管理员只读查看能力 |

迁移应保留现有虚拟库 ID、名称、类型、影片关联、海报和私人库归属，不复制库、不删除源影片。已确认的市场订阅要求不能被旧的公共库放行分支绕过。

迁移使用幂等数据库对账，先保留旧公共库及所属会员库，再建立市场归属和订阅。旧公共库自动上架、归属本站管理员，为已有会员建立初始订阅；客户端仍尊重原有隐藏设置。迁移只初始化一次，不能在后续启动时恢复已关闭的订阅。生产发布前必须完整备份数据。

## 10. 已确认的边界决策

| 事项 | 确认规则 |
| --- | --- |
| 历史公共库迁移 | 自动上架、归属本站管理员，为已有会员保留初始启用；保留原库 ID、内容和海报，原隐藏偏好仍生效 |
| 历史顺序 | 保留可识别的旧个人锚点和 OrderedViews；无法识别时使用默认模板，不再批量覆盖个人 |
| 重新上架 | 原订阅不自动恢复，需手动启用 |
| 作者状态 | 停用、到期、冻结或缺少绑定时暂停分享；会员被删除后保留库及原归属，供管理员只读检查，不自动转移所有权 |
| 上游注入库 | 支持发现并批量接入 TgtoDrive 虚拟库；内容由上游维护，接入后按本人的市场启用状态展示；真实 Emby 实体库保持原有权限 |
| TgtoDrive 初始启用 | 首次接入保留旧用户实际已显示且未隐藏的库；分批接入仍保留首次目录范围，关闭不被同步恢复；后续新增库不自动启用 |
| 新用户默认 | 仅门户首次注册初始化，不作用于自动收编、后台创建、导入、续费或重复登录 |
| 市场预览 | 未启用时仅提供名称、海报等介绍，不展示影片清单和作者影片数量；启用后按本人影片权限读取 |

管理员播放器身份采用显式 Emby 账号绑定，不通过上游管理员角色推断本站作者。绑定账号若同时是会员，两种应用身份使用同一订阅关系；各自的源库编辑权仍分开校验，自有库始终可见、不能被订阅开关隐藏。

## 11. 验收要求

以下是功能验收清单。自动回归范围与执行命令见[测试说明](../tests/README.md)，实际播放器验收仍单独进行：

1. 用户与管理员都能创建、上架、下架自己的库；无审核步骤，无第二份发布副本。
2. 作者改名、换海报、增删关联后，所有启用者读取同一库的最新数据，库 ID 不变。
3. 同一库在作者视图中只出现一次；订阅者不能通过接口改动作者内容。
4. 用户 A 启用后仅影响 A；用户 B 未启用时不能读取播放器库详情、内容或通过库图片接口获取海报，但仍可浏览在架库的市场介绍和预览海报。
5. 关闭订阅后入口及后续访问失效，不删除源库或影响其他订阅者。
6. 作者下架后所有其他用户的订阅及播放器访问立即被撤销，已知库 ID、旧订阅、默认名单和缓存均不能绕过；作者自己的库保留，管理员后台只读查看仍按独立认证权限执行。
7. 管理员可在后台只读查看用户私人库；该能力不让播放器账号越权，也不开放非作者写接口。
8. 注册时仅启用管理员指定且仍在架的默认库；用户自行关闭后，重复登录和重启不会补开。
9. 默认名单修改不影响已有用户；新市场库不因在架就自动展示给所有用户。
10. 个人可跨三种来源混合排序，私人库可移到实体库或订阅库之后，且只影响本人。
11. 新建库、启停、下架及海报／名称更新符合排序表；改默认模板不覆盖个人顺序，恢复默认不改变启用关系。
12. 同时存在多个私人库、多个订阅库和多个原生库时，各发现接口及分页结果完整、无重复、不漏库、总数正确。
13. 无权访问的真实影片不会因市场预览、启用、默认配置或管理员查看功能而获得播放授权。
14. 订阅和顺序重启后保留；历史迁移重复执行不生成重复关系、不改变原库 ID 或重复初始化用户选择。
