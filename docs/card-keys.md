# 卡密管理与兑换

## 管理入口

管理员登录 `/login` 后，从侧栏「卡密」进入 `/login/cardKeys`；手机端从底部「更多 → 卡密」进入。页面提供创建表单、可选祝福文案、卡密列表和复制、编辑、删除操作。手机端列表使用卡片展示，桌面端使用表格。

创建时可填写名称、类型、数量，以及自定义卡的有效期。名称留空时使用类型名称。一次可生成 1–200 张卡；同批卡使用相同的有效期和文案。列表可核对使用状态、兑换邮箱及时间。编辑仅修改名称、到期时间名称和祝福文案，不修改已生成卡的天数或实际到期时间。

## 有效期规则

| 类型或方式 | 兑换后的有效期 |
| --- | --- |
| 试用卡 | 在计算起点上增加 10 天 |
| 月卡 | 在计算起点上增加 30 天 |
| 年卡 | 在计算起点上增加 365 天 |
| 自定义：按天数 | 在计算起点上增加所填天数 |
| 自定义：固定到期日 | 使用指定日期；原会员到期更晚时保留原到期 |

按天数的计算起点为「兑换时刻」与「原会员到期时刻」中较晚者，已有有效时长不会丢失。相对天数卡在兑换前没有确定到期日，因此显示「兑换后 N 天」。没有固定到期日的历史卡继续使用该规则。

固定到期日按服务器时区处理：日历选中的日期归一到当天 `23:59:59.999`，当天仍有效。不同时间兑换同类固定日期卡，目标到期日相同；若原会员有效期更长，续费不会缩短，但该卡仍会核销。固定到期日已过的未使用卡不能兑换，拒绝时不消耗卡。

## 会员使用流程

新会员在门户使用邮箱和卡密开通；已有会员在「我的 → 续费 / 兑换卡密」使用新卡续费。先验证卡密，再发送邮箱验证码，最后提交开通或续费。预检只校验，不消耗卡；真正兑换时服务端再次校验。

同一张卡只能由一个邮箱兑换。已被其他邮箱使用的卡会拒绝；同一邮箱重复提交自己已用过的卡按幂等处理，不重复增加有效期，也不改写原到期名称。重复请求仍需要有效的邮箱验证码，并遵守会员当前的访问规则。

续费不等于解除管理员停用或并发冻结，相关状态规则见 [会员访问与账号恢复](member-access.md)。

## 名称和到期展示

固定到期日卡可填写「到期时间名称」，例如「春节假期结束到期」。兑换后，该名称保存在会员记录中，会员门户与到期提醒邮件优先展示名称，真实日期可作为次要信息；未填写名称则显示真实日期。管理员侧保留真实到期日期，便于核对。

使用另一张卡成功续费时，按新卡更新到期名称；新卡没有名称则清空旧名称。名称只改变展示，不改变后台真实有效期或到期判定。修改卡密文案也不会追溯改写已兑换会员保存的到期名称。

## 祝福文案与 AI 帮写

祝福文案为可选项，可以直接手写。会员在开通或续费时验证卡密成功，只有卡配置了祝福文案才显示可关闭弹窗；未配置时不弹空窗口。每次验证成功都可显示，弹窗内容使用后台保存的卡名、有效期和祝福语。

「AI 帮写」为管理员侧可选功能。先在「系统设置 → AI 文案」启用并配置 OpenAI 兼容的接口地址、API Key 和模型，再使用连接测试或生成文案。默认地址和模型预设为 DeepSeek，使用其他兼容服务时按实际情况修改。未配置时页面提示先配置，不影响手写文案或卡密兑换。

AI 请求由服务端发出，管理接口需要管理员登录；API Key 按密钥设置处理，不返回给会员或作为明文下发到前端。生成结果写入文案输入框，管理员仍可修改，保存卡密后才成为会员可见内容。调用使用管理员配置的 AI 服务额度。
