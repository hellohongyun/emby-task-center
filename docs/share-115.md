# 115 分享转存

在管理后台「系统设置 → 配置项 → TgtoDrive」填写 TgtoDrive 地址和 OpenAPI 令牌，并打开「115 自动转存」。令牌从 TgtoDrive「实用工具 → OpenAPI」创建。TgtoDrive 的「影视发现 → 基础配置」需要设置 115 保存目录。配置保存后生效，关闭开关会暂停领取任务并停止接收新提交。已经开始的转存继续等待结果。

有效、未冻结的会员从门户进入「115 转存」，管理员从后台「115 转存」（`/login/115-shares`）进入。两边都可以粘贴整段分享文案，系统会提取其中的 `115.com/s/…` 或 `115cdn.com/s/…` 链接。每次最多提交 10 条。访问码可放在链接的 `password` 参数中，或紧跟对应链接另写「访问码：1234」。单独的访问码输入框适用于单条链接，选填的补充说明会用于本批链接。

有效链接直接排队，未入队的链接会留在输入框，并标出原批次中的序号和原因。会员只能查询自己的提交和结果。管理员可以查看全部记录，并按会员邮箱、管理员用户名或状态筛选。

每位会员和管理员每小时各可提交 10 条新记录，队列最多同时容纳 200 个排队中或转存中的任务。具有相同分享码和访问码的提交共用排队中、转存中或结果待确认的任务，各提交者分别保留自己的记录。同一提交者重复提交时返回原记录。

| 状态 | 含义 |
| --- | --- |
| 排队中 | 提交已保存，等待后台执行 |
| 转存中 | 后台正在等待 TgtoDrive 返回结果 |
| 已保存 | TgtoDrive 确认保存到 115 网盘 |
| 已存在 | TgtoDrive 确认分享内容已存在 |
| 失败 | 转存被拒绝或管理员确认没有成功 |
| 结果待确认 | 调用超时、中断或缺少可确认的上游响应 |

服务重启后继续领取未执行的任务。执行中断的任务在认领超时后进入「结果待确认」，由管理员核对网盘后标记已保存或失败。已保存仅表示文件进了 115 网盘，Emby 入库由既有流程处理。

后台使用 Bearer 令牌调用 TgtoDrive 的影视资源转存接口，目标为 115，使用观影来源和零积分上限。提交和任务保存在 SQLite 的 `share_115_submissions` 与 `share_115_transfer_jobs`。会员本人及管理员可在记录详情查看原始访问码。系统日志记录任务、提交编号和处理状态。上游返回分享标题时会显示在记录中，目前实测的响应只含转存结果和目标目录，缺少标题时显示会员填写的说明。
