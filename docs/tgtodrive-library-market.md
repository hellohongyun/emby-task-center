# TgtoDrive 虚拟库接入市场

此功能从 1.5.6 起交付。TgtoDrive 提供的虚拟库可以接入本项目市场，由每个用户决定是否在播放器显示，并与实体库、个人虚拟库混合排序。

市场将此类来源显示为「系统自带」，包括来源徽标、维护方、接入面板和排序列表。技术连接仍使用 TgtoDrive，原媒体库名称和订阅关系不因显示文案调整而改变。

## 配置与接入

1. 系统设置配置 Emby 地址，以及可读取媒体库和用户目录的 API Key。优先使用真实 Emby；也兼容两处均使用同一 TgtoDrive Emby 反代入口的现有配置。
2. 虚拟库反代的上游填写 **TgtoDrive 的 Emby 反代入口**。TgtoDrive 管理台地址不能代替该入口；两端必须连接同一台 Emby。
3. 在工作台顶部绑定管理员播放器账号，用该账号范围发现来源媒体库。
4. 打开「媒体库市场 → 系统自带媒体库接入 → 管理接入」，点击「同步来源列表」。
5. 勾选候选库，或点击「全选待接入」，再批量接入。接入后自动上架市场，可由管理员下架或重新上架。
6. 用户在市场自行启用或关闭。播放器继续连接本项目反代，使用原 Emby 账号；调整顺序后在播放器刷新。

若待接入数量为零，先确认虚拟库能从配置的 TgtoDrive Emby 反代入口返回。两处均使用真实 Emby 直连且未注入虚拟库时，不会发现额外虚拟库。服务器标识不一致、目录读取失败或分页不完整时，不更新已有来源可用状态。

## 识别与数据边界

同步先核对两端的 Emby 服务器标识。两处地址不同时，比较同一账号的媒体库目录和实体库列表；两处是同一 TgtoDrive 入口时，使用显式根级 `CollectionFolder` 实体查询和 `Library/VirtualFolders` 作为参照，再对比注入后的 Views／MediaFolders。通过原始 Id／Guid 排除实体库，并排除内置合集、播放列表等非目标类型。候选需要管理员确认接入，接入时重新读取来源，拒绝过时或已变为实体库的候选。

外部库以「来源地址＋原始库 ID」生成稳定市场标识。市场只保存介绍、来源、上架状态、订阅关系和迁移进度，使用独立的 SQLite 表，不创建本地影片关联、不复制片单，也不提供修改 TgtoDrive 内容的入口。来源切换后使用不同的登记范围。

名称与海报元数据通过再次同步更新；影片内容、详情和播放器图片继续由 TgtoDrive 提供。网页市场的海报预览经过认证后只读代理，缺图或读取失败使用系统默认图。

## 订阅与首次接入

- 首次接入保留已有有效账号当时能看到、且未在个人偏好中隐藏的库。首次目录中的库可分批接入，不会因为分批而丢失初始启用。
- 初始迁移逐库记录完成情况；读取失败保留待重试。同步页面显示尚待核对的账号数，再次同步可继续，不覆盖已保存的开关。
- 为避免大量账号或慢网络拖住同步，每批最多并行核对四个账号，并限制单次处理时长；同步和接入网页请求允许等待最多 120 秒。
- 后续新接入市场的来源库不自动给旧用户启用；未接入的库继续沿用上游行为。新注册用户仍只使用管理员明确选择的默认名单。
- 关闭只影响本人。管理员下架或同步确认来源移除后撤销访问；重新上架或来源重新出现，均需用户手动启用。

这里管理虚拟库入口和组织范围，不增加影片播放权限。通过本项目反代的库列表、首页分区、直接详情、ParentId 查询、图片及已识别别名都受当前订阅控制；原实体库、原影片和播放继续遵守上游账号权限。市场介绍海报仍可在启用前预览。

部分上游仅在 Views 中注入虚拟库，显式根目录查询仍只返回实体库。反代会使用已经验证的播放器账号及原凭据读取 Views，只补齐该账号已启用且上游实际返回的库，再统一排序和分页；不会用管理 API Key 为播放器补库。

若来源忽略请求中的 Limit 并返回完整媒体库目录，反代会在筛选订阅、合并自有库及排序后保留完整列表，避免末尾入口被再次截断。来源实际支持分页时仍按页返回，包含正确的总数。

启用市场库不会创建影片。库内内容仍取决于 TgtoDrive 针对该账号返回的结果；上游返回空列表时，播放器库内也为空，首页影片行还取决于上游分区与客户端支持。排查时应分别核对媒体库入口、库内影片和首页分区。

## 验证范围

本地 HTTP 与浏览器夹具覆盖目录区分、跨后端拒绝、分页、批量接入、初始启用与隐藏偏好、关闭及下架、Guid 别名、首页分区撤权、个人排序和重启保留。测试不访问真实用户数据、不发送邮件、不对 TgtoDrive 执行业务写操作。实际 TgtoDrive 部署和各播放器版本仍需联调验收。
