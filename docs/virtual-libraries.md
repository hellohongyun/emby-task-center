# 虚拟媒体库

本文描述 1.5.6 的市场与个人排序实现。需求及验收边界见[虚拟媒体库市场与个人排序需求](virtual-library-market-requirements.md)。

管理后台的「虚拟媒体库」（`/login/virtual-libraries`）用于额外组织 Emby 已有内容。创建虚拟库后，从 Emby 实时搜索并选入影片；原有媒体库继续保留。虚拟库只保存关联，同一影片可以加入多个虚拟库，不复制文件，不修改原影片资料。

「已加入的内容」使用与媒体库一致的海报卡片网格，展示原影片海报、名称、年份和类型；缺图或加载失败时显示占位。卡片保留移除关联操作，类型不匹配时仍显示告警。

手机端将虚拟库列表与内容区上下排列，已加入和待选择内容均以双列海报展示。我的库、市场、用户库查看、新用户默认设置及排序列表均显示媒体库封面；封面使用固定比例容器完整展示，不裁切竖版海报。创建、编辑和反代表单按手机宽度排列，搜索、分页和操作按钮支持触摸；桌面端保留侧栏与内容区并排布局。这里适配的是管理网页，Emby 客户端界面仍由各客户端提供。

## 配置与使用

1. 在「系统设置」配置 Emby 地址和 API Key，作为管理端选片的信息源。
2. 打开「虚拟媒体库」，创建媒体库，选择类型、名称和排序，再搜索、勾选并加入已有内容。「从 Emby 选择内容」只查询电影（Movie）和整部剧（Series），不单独选择季、分集或其他类型；分页总数由上游按作品类型筛选后返回。电影库只允许电影，剧集库只允许整部剧，混合库允许电影和整部剧。客户端会根据库类型筛选内容，不兼容的条目会提示原因并禁止加入；需要混放时选择混合库。
3. 在同页的反代设置填写 **TgtoDrive 的 Emby 反代地址**，不是 TgtoDrive 管理台地址。留空时沿用系统 Emby 地址。
4. 设置独立监听端口（默认 `8097`），启用并保存。页面显示实际运行状态；端口被占用时保存失败，已有监听与已保存配置保留。
5. 在 Emby 客户端添加服务器，地址填写本服务的反代入口，例如 `http://服务器地址:8097`，继续使用原来的 Emby 账号登录。通过 HTTPS 部署时可将独立域名反代到该端口，需支持 WebSocket 升级。

初次安装不会自动启动新的监听；启用后自动随应用启动，配置、虚拟库和关联持久化到现有 SQLite 数据库。改变端口或停用会断开旧反代连接。

## 个人专属私人库

管理员和会员都在「虚拟媒体库 → 我的虚拟库」维护自己创建的库，可创建、改名、选择电影／剧集／混合类型、搜索添加已有作品、移除关联及维护独立海报。新建库默认不上架，本人始终可见；管理员创建的库不再自动向全员展示。删除库只删除该库及关联，不删除原影片。反代地址、端口及启停仍由管理员统一配置。

私人库绑定会员身份，门户使用会员会话校验归属；需会员有效、未冻结且绑定 Emby 账号才可使用。选片搜索、来源媒体库及新增影片校验使用绑定账号的 Emby 用户范围，不扩大影片权限。私人的是库名称、封面和选片组合，加入私人库不会隐藏原公共库里的影片。

Emby 客户端必须连接本项目反代，使用自己的 Emby 账号登录。反代通过原客户端凭据向上游确认身份，再读取当前会员绑定；不把路径或查询中的 `UserId` 作为身份凭证。其他账号看不到该私人库，也不能通过库 ID 读取详情、内容、最新分区或封面。私人封面即使携带当前图片 tag 也需本人认证；客户端若不附带凭据，可能无法显示私人库海报，不能用市场库海报 tag 绕过订阅或归属校验。

身份绑定来自反代转发的成功 Emby 登录响应，不依赖 Emby 不提供的 `/Users/Me`。首次升级后，如果播放器仍使用原有登录态，需要在本项目反代入口退出并重新登录一次；仅登录会员门户不能建立播放器令牌的身份绑定。绑定仅保存令牌哈希、上游范围及账号 ID，后续私人库读取仍用原令牌向上游验证有效性。绑定随现有 SQLite 数据保存，服务重启后可继续使用，最多保留 90 天，到期需重新登录；无法确认身份时不展示本项目虚拟库，其他上游请求继续按原规则处理，不猜测所属账号。

登录识别支持 `/emby` 前缀、登录接口的 `.json` 后缀、gzip／deflate／br 压缩及 UTF-8 BOM。解析使用受限副本，压缩前后最多 1 MiB，客户端仍收到原始响应字节。客户端授权元数据中的空 Token 不再覆盖有效的独立令牌；多个非空令牌冲突时仍拒绝确认归属。上述兼容由本地 HTTP 回归验证，SenPlayer、Yamby、Hills、VidHub 的实际版本仍需设备联调验收。

私人库未显示时，在「系统日志」搜索「私人库诊断」或事件 `virtual_library_identity`。日志区分登录响应解析、身份保存、凭据复核和会员绑定，成功确认范围时记录私人库数量；仅记录固定客户端类别和原因，不记录账号、原始请求头、令牌或影片名称。重复的同类发现请求每分钟记录一次；详见[运行故障排查](runtime-diagnostics.md)。

媒体库顺序按「管理员默认模板＋个人顺序」保存。私人库默认置前，但本人可与实体库、订阅库混合移动，不再强制置顶。媒体库改名、换海报或修改内容不会改变 ID 和已保存的位置。

私人库、市场状态、订阅、个人顺序、映射及海报保存在同一 SQLite 数据库中。升级将旧公共库归属到本站管理员并自动上架，为已有会员建立初始订阅，保留原库 ID 和内容；迁移不会在后续启动时恢复用户已关闭的订阅。管理员通过独立的「用户库查看」只读检查会员私人库及关联，不能通过自己的库写接口代编辑、代删除或代上架。

「用户库查看」使用紧凑的选库侧栏与内容区，首次载入自动选择首个库。影片以 2:3 海报卡片展示片名、年份和类型，可在当前库按片名／年份搜索和类型筛选；手机端默认收起选库区域，点击「切换媒体库」展开搜索和横向列表，选库后自动收起，影片以双列展示。缺图或图片加载失败显示明确兜底，读取失败支持重试，空库与筛选无结果分别提示。此页面无需绑定管理员播放器账号，不展示该绑定提示。

影片图片使用管理员专属的用户库关联接口：仅允许读取已关联到该用户库的影片，支持数字与非数字来源 ID；即使历史记录缺少图片 tag 也可尝试读取。接口只取图，不修复关联或修改库内容，不向前端暴露 Emby API Key，取消图片请求时同步中断上游读取。

## 名单逐项选片

在选片区上方粘贴片名名单，每行一个电影或剧名，点击「开始逐项选片」。页面自动搜索当前片名，你仍按原方式选择一个或多个版本并点击「加入已选」；加入成功后自动搜索下一项，失败时保留当前片名和勾选结果。没有合适结果或已经加入时可「跳过此项」，不会自动匹配或自动加入。

搜索沿用当前源媒体库筛选和原有类型校验。空行会忽略，重复片名保留。可以随时结束名单，已加入的关联保留；切换虚拟库会结束当前名单。名单和进度只在当前页面内暂存，刷新或离开页面后不保留。

## 虚拟媒体库市场

作者在「我的虚拟库」自主上架／下架，无需审核。市场与私人管理始终指向同一个库；名称、海报和影片关联由创建者维护，订阅者读取最新内容，不产生独立副本。

其他用户在「媒体库市场」启用后，库才出现在自己的播放器中；关闭只影响本人。市场介绍只展示在架库的名称、海报等基本信息，不向非作者暴露影片清单或作者的影片数量。启用市场库不会扩大原 Emby 的影片权限。

作者下架后，订阅者对库详情、内容和海报的服务端访问立即撤销，客户端刷新后移除入口；作者自己的库及管理员后台只读查看仍保留。重新上架不会恢复旧启用，需用户再次手动启用。作者到期、停用、冻结或失去绑定时暂停分享；删除会员后保留库供后台检查，不转移所有权。

管理员在「新用户默认设置」勾选一个或多个在架库，只在门户新会员首次开通时初始化订阅；续费、重新登录、重复开通和默认名单修改不覆盖已有选择。手工建会员、自动收编和导入不自动套用该名单。

工作台顶部提供独立的「管理员播放器账号」面板，显示绑定状态并允许更换账号，用于识别管理员自己创建的库及个人订阅；不要求创建会员，也不通过上游管理员角色推断归属。若绑定账号本身也是会员，两处市场开关使用同一份订阅，避免一处关闭、另一处又使库出现。作者编辑权仍由当前应用身份分别校验。

市场卡片分别显示「自己创建／账号自有／已启用／未启用」状态和可执行动作，支持按状态筛选及名称／作者搜索。自己的库列表直接显示上架状态，分享开关说明其对订阅者的影响；播放器反代已运行时配置面板默认收起，保留运行状态和连接地址。

排序页显示当前使用默认或个人顺序、可见库分类数量和显示序号。排序及新用户默认名单提供保存／未保存状态，失败保留修改；可撤销本次修改，切换工作台标签时提示尚未保存的内容。播放器绑定与新用户默认名单分别保存，互不覆盖；更换账号前需先处理当前页面的未保存修改。

## 客户端媒体库顺序

「我的媒体库顺序」统一展示当前用户可见的原生库、自有库和订阅库，可拖动或使用上移／下移保存混合顺序。新建私人库默认插到最前，新启用订阅库追加到当前末尾；关闭或下架仅移除对应入口，不打乱剩余库。排序先校验可见范围，库 ID 出现在旧顺序中也不能绕过撤权。

没有新个人顺序时，先保留可识别的旧个人设置，否则使用管理员默认模板。恢复默认后使用当前模板，私人库默认置前，模板外库保留相对顺序；不恢复已关闭的订阅。个人顺序跨刷新、登录及服务重启保存。

### 管理员默认媒体库顺序

1. 在工作台或默认排序页顶部的「管理员播放器账号」面板选择对应账号，确保源 Emby 和反代上游连接同一服务。
2. 打开侧栏「媒体库顺序」（页面为默认模板），排列当前账号可见的上游库及市场库并保存。
3. 模板只保存在本项目，不向所有 Emby 账号批量写入 OrderedViews，不覆盖已经保存的个人顺序。旧的全量同步 API 不再注册。

TgtoDrive 动态注入库在市场显示为「系统自带」，管理员可在「系统自带媒体库接入」面板同步发现并批量接入，用户随后自行启停、混合排序；未接入的上游库继续沿用上游行为。实体库与 Emby 自带合集通过直连目录排除，不能仅凭名称或 CollectionFolder 类型识别。接入说明见 [TgtoDrive 虚拟库接入市场](tgtodrive-library-market.md)。原始 DTO 和 Guid／Id 别名保留，内容不复制为本地虚拟库。客户端请求继续携带自身凭据，确认完整列表后合并排序再分页。客户端自行重新排序或缓存列表时，实际界面需单独验证。

## 首页与客户端发现

- Emby 4.10 首页使用 `HomeSections` 和 `Sections/{sectionId}/Items`，与侧栏的 `Views` 不同。反代按分区的 `SectionType=userviews` 识别媒体库行，合并虚拟库；继续观看、TTD 自有分区和其他分区保持原上游结果，不写死分区 ID。
- 上游已启用标准 latestmedia 首页行时，为本项目虚拟库追加独立「最新内容」行和对应分区内容接口；原有分区与顺序保留，不复制原库的题材、工作室等筛选。只处理本项目分区 ID，隐藏设置仅影响新增行。
- 首页分区分类按上游、用户及凭据隔离，最多缓存 60 秒，每次成功读取 `HomeSections` 刷新；只保存分区 ID 和类型，内容请求仍逐次鉴权。
- `/Library/MediaFolders` 和包含本项目虚拟 ID 的批量 `/Items?Ids=...` 也能发现虚拟库。批量请求只从上游查询参数中移除本项目 ID，保留其他参数及上游返回的全部条目；仅包含本项目 ID 时先使用原客户端凭据鉴权，避免空 `Ids` 扩大查询。纯上游 ID 和真实父范围请求直接透传。
- 部分客户端（如网易爆米花）通过用户根级 `Items` 获取媒体库。仅对无父范围、无 IDs、非递归且筛选参数受支持的请求，在上游成功返回非空、全部为 `CollectionFolder` 的列表后追加本项目库。原查询、上游条目字段与相对顺序保留；空结果、普通影片结果、搜索和不支持的筛选保持原响应，不扩大到全库扫描。
- Views、首页媒体库行与 MediaFolders 沿用客户端原始列表请求，不移除分页、改写 Fields 或扫描上游其他页。保留所有上游 DTO、扩展字段及相对顺序；上游超额返回的 TgtoDrive 条目也不裁剪。普通分页在上游末页剩余空间或后续页追加本项目条目，不重排上游分页。
- 这些是代理入口中的逻辑库，不会在 Emby 原服务建立物理媒体库或伪造磁盘目录。直接连接原服务仍看不到它们。

## 请求与数据行为

- 浏览接口额外展示虚拟库，库内内容返回原 Emby 条目 ID 和实时资料。搜索、排序、分页和递归剧集查询由虚拟库查询层与上游共同完成。
- 虚拟库的 CollectionFolder 在根列表和详情中均提供客户端需要的 `Subviews` 数组：电影库包含 `movies`，剧集库包含 `series`，混合库包含两者，并保留题材、文件夹子视图。此字段用于 Emby 客户端创建浏览标签，避免打开库时读取缺失数组报错。
- 登录、真实条目详情、播放信息、字幕、收藏、已看、进度和其他接口继续转发给 TgtoDrive。播放流保留 Range、状态码及外部直链重定向；WebSocket 双向转发。
- 类型校验只作用于本地虚拟库映射的新增和类型修改，不改变原媒体库或代理请求。前后端使用同一规则；批量加入包含不兼容条目时整批拒绝，避免部分加入。修改库类型与已有内容冲突时会提示并阻止保存；可改为混合库或先解除不兼容关联。
- 历史已保存的不匹配关联会保留并提示，不会自动删除或改库类型。已加入列表会说明可能在客户端不可见的原因；改为混合类型后刷新客户端，无需重新添加。
- 已保存的季、分集等历史关联继续保留；新增关联接口按 Emby 实际类型校验，只接受电影和整部剧。选中整部剧后，客户端仍通过原 Emby 条目浏览季、分集和播放。映射保存当前 Emby ID，以及上游可提供的 TMDB ID；不因同名或同 TMDB ID 自动合并多个来源。
- 本项目所有虚拟库均校验已证明的账号身份，再计算本人库及有效在架订阅；无法确认身份不放行旧公共库。原始媒体请求继续透传，不替代原服务器鉴权；不使用管理后台 API Key 为播放器扩大权限。
- 管理后台「移除」只解除关联；删除虚拟库只删除本地虚拟库和关联。客户端原有的真实媒体删除请求仍发送到上游，成功后清理对应虚拟关联；实际删片行为与权限由上游决定。
- 每个虚拟库可在对应管理页的「媒体库海报」上传、预览、替换或移除独立封面（JPEG／PNG／WebP，最大 5 MiB）。海报原始字节与元数据存入同一 SQLite 数据库，随 data 备份和迁移，无需额外挂载图片目录。优先使用作者上传的封面；未上传或移除后统一恢复系统内置海报，不再自动取关联影片封面。网页图片加载失败也回退到内置海报。播放器默认封面提供 PNG，网页使用同款 SVG；默认图不依赖外部图片服务。仅覆盖虚拟库入口封面，不修改实体库或库内影片、剧集的海报和资料。播放器图片请求无论 tag 是否匹配，都需确认当前账号可访问该库；市场预览使用独立的认证接口，只允许读取仍在架库的介绍海报。管理海报需创建者身份，管理员只读查看走独立后台接口。排序列表的虚拟库封面也校验当前可见范围，订阅关闭或作者下架后不能从排序封面入口继续读取。自有库 DTO 提供稳定标识、封面元数据和中性 UserData，不继承关联影片的播放状态，不修改原条目的资料或权限。

系统默认海报源文件为 `packages/contracts/src/library-poster.ts`；修改后运行 `node scripts/generate-library-poster.mjs` 同步内置 PNG，并在画面变化时更新默认图片 tag。生成命令需要 Node 24 和已安装的 Playwright Chromium，运行服务无需浏览器或额外图片目录。
- 直连 TgtoDrive 或原 Emby 的客户端不会看到本服务新增的虚拟库；必须连接新反代入口。

## 海报压缩与慢网络上传

管理员和会员的海报管理页会在上传前自动处理所选图片：保持比例，最长边最多 1600 像素，优先编码为 WebP（质量 0.82，保留透明区域）；若处理后体积更大，则保留原文件。页面展示压缩状态和前后大小，处理完成后才能保存。选择其他图片、切换媒体库或离开页面时，旧处理结果不会覆盖新选择。损坏或无法解码的图片显示错误，不自动上传。

所选文件仍限 JPEG、PNG、WebP，原始文件最大 5 MiB；服务端保留原格式、大小与尺寸校验。数据库保存实际提交的图片字节，旧海报不会批量重写。海报上传等待时间延长为 120 秒，其他请求继续使用原有超时；上传失败保留选择，便于重试。部署中的网关或反向代理也需允许相应上传时长，其独立超时不能由网页延长。

## 浏览性能

需要展开映射容器时，子项发现查询会沿用请求的非空 `IncludeItemTypes`，避免客户端只要作品却先读取全部分集；合法匹配的 Video、Episode 等子项仍保留。播放状态等其他筛选继续在最终查询执行，不用于提前裁剪子项范围。SenPlayer 安卓端已由使用者确认首页、库封面和库内内容可以显示；曾反馈一次库内加载失败，本地请求复核未复现，仍需继续观察，不能视为长期稳定性保证。

当列表明确只请求电影或整部剧（`IncludeItemTypes=Movie/Series`），并且当前映射全为作品条目时，递归参数不会触发读取全部季和分集，直接使用已映射的原 ID 查询，上游继续执行筛选、排序和分页。作品库的题材、年份等筛选默认读取作品资料；明确的季、分集、继续观看及未限定类型的完整数量统计仍保留相应范围。历史文件夹等容器仍按原规则展开，避免遗漏其中内容。NextUp 直接查询真实映射父项，无需预先遍历所有分集。

这项优化不缓存媒体列表或播放响应，也不跨用户共用筛选结果。分集、详情与播放仍使用原上游条目。虚拟库的分组最新内容请求携带 `MediaTypes=Video` 时，按电影和整部剧读取作品，避免将没有叶级 MediaType 的剧集容器错误排除；仅音频筛选、明确不分组的请求和普通库透传不变。

Hills 等客户端的虚拟库首页「最新内容」默认按作品展示：映射全部为电影和整部剧时，直接批量读取这些作品，默认按作品添加时间（DateCreated）倒序排列，不为排序遍历全部分集。客户端明确指定的排序仍保留；这不代表按最新分集更新时间排列。整部剧使用原 Emby 剧名、ID 和海报。显式 GroupItems=false 的分集内容、继续观看、NextUp 和进入剧集后的季／分集浏览保持原语义。历史容器展开时，通过真实父范围建立分集归属，避免多来源合并后 SeriesId 别名造成分组错误。

## 原条目 ID 变化后的关联恢复

管理端读取「已加入的内容」时检查当前关联；客户端访问虚拟库内容、详情或封面时也会检查。检查按虚拟库、上游地址、用户上下文、认证凭据与映射身份快照隔离，结果短暂缓存 30 秒；同一上下文的并发请求共享检查，分页、筛选、Accept 等无关参数不重复检查。新增或移除映射后重新检查；自动修复得到的新快照可继续复用刚完成的检查。失败、鉴权拒绝与取消不作为成功缓存，等待方可用自身请求重试。没有明确用户的封面请求不会被当成某个显式用户请求共享结果。缓存只覆盖身份检查，正常查询仍逐次交给上游鉴权。仅虚拟库范围触发检查，普通媒体库、真实条目和播放请求仍直接转发。

新增关联会记录 Emby 提供的有效 TMDB ID。已存在的原 ID 仍有效且类型相同的旧关联可补齐该身份；原 ID 已失效且旧记录没有 TMDB ID 时不按片名猜测。原 ID 失效或指向其他身份后，仅当上游查询到**同类型、同 TMDB ID 的唯一候选**时更新本地关联，保持排序和虚拟库归属。候选为空、多个来源、上游读取失败或身份不能确认时保留关联，管理端显示具体原因并提供刷新、重新选片的提示，不静默删除。

检查最多等待 10 秒，超时保留关联并显示重试提示；不会在迟到的查询返回后补写关联。检查期间已移除或修改的关联不会被旧结果恢复或覆盖。数据库仅新增可空身份列，历史映射保留。此恢复只更新本地映射，不改变上游影片、权限、播放链接或合并策略；客户端检查始终使用原客户端凭据，不借用后台 API Key。

## Docker 端口

生产 Compose 使用 Host 网络，管理端口为 `12333`。启用虚拟库反代后，应用会直接监听后台设置的宿主机端口（默认 `8097`），不需要修改 Compose 或增加端口映射；只需确认该端口未被占用并在防火墙放行。

修改反代监听端口后重建容器即可生效。源码构建和隔离测试使用的 `compose.build.yaml` 采用桥接网络，才需要为反代端口增加与后台监听端口一致的 `ports` 映射。

## 验证范围

自动测试使用临时数据库和本地 Emby HTTP 夹具，覆盖 Emby 4.10 首页分区、自有条目的排序和隐藏、原配置透传、批量发现、鉴权及流量透传。另对实际 TgtoDrive／Emby 4.10.1.0 上游只读比较：首页媒体库行、Views、MediaFolders 在原始及带分页参数的请求下，均完整保留 40 个上游条目及其 DTO，再加入本项目两个库。

官方 Emby 网页端通过本地验证代理连接该真实上游，已核对首页实际请求与上游结果一致，15 个 TgtoDrive 虚拟库与本项目两个库均有卡片。这不是远端生产服务已更新的证明。本地修复后的媒体库排序、Hills 库展示与作品海报已由使用者测试确认；默认首页按作品添加时间显示电影和整部剧。Yamby 2.1.0.11、VidHub 和网易爆米花的本地虚拟库显示问题也已由使用者测试确认。SenPlayer 安卓端的显示已获使用者实机确认，但偶发加载失败仍需观察；Infuse 尚待实机验证。不能用 API 或网页测试代替客户端验收。
